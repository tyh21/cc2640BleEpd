## Usage
* build cc2640r2 project and flash to the device
* build Android app, and open it on phone
* connect the the device with name like 'simple peripheral uarttrans'
* use any tool you like to convert image to lcd data, (https://www.waveshare.net/w/upload/3/36/Image2Lcd.7z)
* load black image bin file (2756 bytes, 104x212)
* load red image bin file
* click download, and wait the device to receive and update

## cc2640r2 project Dev
Iar 8.11  (it is recommended that no blank space in stall path)
TI ble5 sdk: simplelink_cc2640r2_sdk_1_40_00_45

* sdk is installed into default location: c/ti/simplelink_cc2640r2_sdk_1_40_00_45/
* create a folder named 'CC2640R2_LAUNCHIOT' in sdk's example/rtos/
* move whole folder to /c/ti/simplelink_cc2640r2_sdk_1_40_00_45/examples/rtos/CC2640R2_LAUNCHIOT/ble5stack/5.14_advance_peripheral_uarttrans
* move 'target' folder to /c/ti/simplelink_cc2640r2_sdk_1_40_00_45/examples/rtos/CC2640R2_LAUNCHIOT/ble5stack

You don't need to follow the above steps. If that happens, you need to adapt your project to your real case.
The target folder contains pin configs for the device.



## Command-line build (scripts at repo root)
Firmware (IAR):
    set IAR_PATH=C:\Program Files (x86)\IAR Systems\Embedded Workbench 8.0
    build_fw.bat v7            -> out\BleEpd_fw_v7.hex  (+ .out)
Android app (Gradle):
    build_app.bat v33          -> out\BleEpd_app_v33.apk
Both:
    build_all.bat v7 v33

* build_fw.bat runs IarBuild.exe on two projects and copies artifacts into out\:
      stack\cc2640r2lp_stack.ewp   -build FlashROM_Library
      app\cc2640r2lp_app.ewp       -build FlashROM_StackLibrary
  Both get -varfile ...5.14_advance_peripheral_uarttrans.custom_argvars
  (that file supplies SIMPLELINK_CORE_SDK_INSTALL_DIR / SRC_BLE_DIR / ...).
* IarBuild.exe is auto-detected under common install paths, or set IAR_PATH.
* Requires the TI SDK at C:\ti\simplelink_cc2640r2_sdk_1_40_00_45
  and xdctools_3_50_02_20_core at C:\ti\xdctools_3_50_02_20_core.
* Verified building with IAR Command Line Build Utility V8.0.15.5379.
* build_app.bat auto-picks a JDK if JAVA_HOME is unset or wrongly points at a \bin
  subfolder (it falls back to Android Studio's bundled jbr).

## power (B1)
* POWER_SAVING is now enabled (app .ewp define) and Power_init() is called in
  main.c (the stock Board_init() had been replaced by a bare PIN_init(), so the
  Power driver was never brought up and the device never entered STANDBY).
* Policy: PowerCC26XX_standbyPolicy
  (target/LAUNCHIOT_CC2640R2MOD_RGZ/LAUNCHIOT_CC2640R2MOD_RGZ.c).
* Tunables (power vs. responsiveness):
    NFC_POLL_MS                    nfc_esl.c, default 1 ms; raise to cut idle wake-ups
    DEFAULT_ADVERTISING_INTERVAL   peripheral_uarttrans.c, 160 = 100 ms
    DEFAULT_DESIRED_(MIN|MAX)_CONN_INTERVAL  16 = 20 ms
* NFC IRQ: the FM11NC08S IRQ_N (active low) is wired to DIO_13.  The NFC task
  arms a falling-edge interrupt on it and sleeps in Event_pend; the poll is
  only a fallback.  NFC_FALLBACK_MS (nfc_esl.c, default 200 ms) is the tunable.
  Verified on hardware: the chip asserts IRQ_N by default, so no SYS_CTRL /
  INT_MASK setup is needed (see doc/FM11NC08(1).pdf).
  The loop's housekeeping timers (EPD_WAIT_MAX, IMG_HOLD_MAX, CH_STALL_SLOTS,
  PANEL_RETRY_SLOTS, LOOP_IDLE_FLUSH, the busy-flag decay) are all in ms and
  advance by real elapsed time, so NFC_FALLBACK_MS can be raised freely (0 =
  IRQ-only, no periodic tick - but then that housekeeping stops).
* Bench-check after flashing: idle current with no tap, tap responsiveness,
  BLE connect/throughput, and that a tap right after a long idle still works.
* To revert quickly: set the app .ewp define back to xPOWER_SAVING.
